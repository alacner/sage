# Sage 是什么

Sage 是面向项目的桌面 AI 工作空间：以项目目录为边界，把对话、文件编辑、工具调用和插件扩展放在一起。数据默认保存在项目 `.sage/` 目录，便于备份与迁移。

## 开始使用
1. 添加项目目录，侧栏即出现项目与对话列表。
2. 在设置中配置模型提供商或 CLI 引擎插件（见「模型与后端」「CLI 引擎插件」）。
3. 创建对话，输入需求即可开始；默认仅内置 API 直连引擎。

## 界面布局
左侧边栏管理项目、对话与插件入口；顶部标签页打开对话、文件与插件页面；底部状态栏显示运行模式与用量。随时通过 设置 → 关于 → Sage 帮助 打开本帮助，按功能名或问题搜索。

# 首次配置引导

新版配置引导先询问连接方式。Sage 需要 API 直连或已安装、启用并配置的 CLI 引擎插件。中继属于 API 连接方式，可以统一提供授权模型。引导不会代填密钥、自动申请 Token 或发送对话。

## 使用中继
1. 选择「是，使用中继」，进入中继连接设置，填写服务商给出的完整连接地址。
2. 回答是否有 Token。有则粘贴到 Token 输入框；没有则点击旁边的「申请」，在中继站点申请后返回填写。申请按钮只在地址对应的申请页可访问且 Token 为空时出现；没有入口时检查地址或向中继服务商索取 Token。
3. 点击「连接」，等待「已连接」。填完后若已自动连接，可直接继续。
4. 进入模型设置，等待中继提供商和授权模型自动出现，首次同步可能需要一会儿。连接成功不等于模型同步完成；一直没有模型时检查 Token 的模型权限，不要手动重复添加中继提供商。
5. 中继复用已有的模型能力数据，通常不需要本机重复验证，接着选择全局模型。没有已确认的视觉能力时可暂时跳过视觉模型。

## 自定义提供商
1. 不使用中继时，选择配置模型提供商，点击「添加提供商」，或选中已有的普通 API 提供商。
2. 依次填写名称、API Host，确认 API 协议（OpenAI Chat Completions 或 Anthropic Messages），填写 API Key。API Host 使用厂商文档中的完整 API 基础地址，按文档保留 /v1 等路径，不是官网首页。没有密钥输入行时点击「+」。
3. 点击「测试连接」。如果取得模型列表，会自动保存并提示提供商配置完成。如果接口不支持获取列表，引导明确要求手工填写准确模型 ID：在模型列表点击「编辑」，输入 ID、按 Enter 添加，再点击「完成」。
4. 空列表与连接失败不同：空列表时检查账号模型权限或手工填写；鉴权、网络等失败时先根据错误修改配置并重试。不要把失败当成配置成功。
5. 点击「查看模型能力验证」，再点击「重试所有未验证项」。验证会实际调用提供商，等待本轮完成。未验证项为 0 时可直接继续；仍有未知项时查看原因并重试，或先选择能力已确认的模型。未知不表示支持。

## 选择全局模型
- 全局默认模型：日常对话、推理和工具执行的主模型；项目或对话未指定其他模型时继承它。选择支持对话和工具调用的模型。
- 全局视觉模型：用于读取图片、截图并提取信息，主模型不能直接看图时可用于视觉处理。选择器只列出已确认支持视觉的模型。同一模型可以同时承担两种角色；没有视觉模型时可暂时跳过。
- 等待自动保存成功后继续。保存失败时先在设置页重试，不能把未保存的配置当成完成。

## CLI 与自行探索
选择「使用 CLI 插件」后，到插件市场安装所需引擎并全局启用，按插件说明安装 CLI 并完成登录或 API 配置。确认 CLI 检测和认证状态后，到「通用」选择该引擎。CLI 的模型与认证由对应插件管理，不要求先配置 API 全局模型。也可选择「自己探索」结束引导。

## 对话与帮助
配置后选择项目文件夹，点击侧栏「对话」旁的「+」新建对话，也可点击引导中的「新建对话」。输入需求后自己发送。点击左下角「?」打开帮助，直接在搜索框描述问题，例如「如何添加模型」「中继连不上怎么办」；帮助检索本地操作文档，不需要调用模型。

## 展示与恢复
这是新的第 2 版引导。首次使用或此前只看过旧版引导的用户会自动看到一次；看过新版后，普通安装包升级不再重复显示。在「设置 → 通用 → 新手引导 · 新版」可以随时重新打开。引导可随时结束、返回上一步，或用「定位当前操作」回到对应设置控件；已有配置不会被清空。明确选择 API 连接方式时会把后端切换为 API 直连。

# 对话、队列与重新发送

对话支持文字、图片和附件，执行中发送的新消息可进入队列。

## 发送与插话
输入框提示当前使用的发送、换行和插话快捷键。插话与排队不同：插话可在工具调用间隙补充当前任务要求，排队消息等当前轮结束后按序处理。

## 重新发送
失败回复上的重新发送会替换该轮的用户问题与失败回复，避免重复气泡。运行中不能重复启动同一轮。

## 附件上限
设置 → 对话可配置单张图片上限（默认 5 MB）和文本文件内联上限（默认 1 MB）；超限图片被拒绝，超限文本退化为仅附路径。


## 边界与注意
已完成的外部操作（命令、写入、网络请求）不保证可以安全重放，重新发送前先核对实际结果。


## 发送前确认
检查当前项目、对话、模型与安全方案。输入文字，可添加图片、文件引用或能力标识。普通输入与语音转写都先进入草稿；发送前可编辑。正在执行时追加消息按界面的队列/插话操作处理，避免把多次点击当成独立执行确认。

## 修改和重新发送
编辑历史用户消息前先确认将从哪一轮继续；重新发送可能重新调用模型和工具。之前已写入文件或外部系统的结果不会因为修改消息自动撤销。先检查已有结果，必要时在新指令中说明哪些工作已完成。

## 草稿与附件
切换对话时草稿按对话保存；删除附件只移除待发送内容。发送失败时先检查错误与当前消息状态，避免盲目重复执行具有外部副作用的请求。

# 对话全文搜索

对话变多后，在 设置 → 对话（对话管理页）顶部的搜索框输入关键词，即可跨全部对话全文检索，活跃与归档分组都会匹配。

## 搜索范围
支持三层：对话标题、消息内容、对话记忆。结果行用徽章标出命中的是哪一层，便于判断要不要打开。

## 后续操作
搜索结果中可直接对对话执行常用操作：配置对话记忆、复制对话 ID、归档/解档、删除。

# 专家团与执行计划

专家团由项目经理拆分任务，按依赖关系调度专家执行。

## 执行模式
输入框左下角可选择执行模式：自动、智能体、专家团。自动档在提交第一句话时按复杂度选择：含专家团/团队协作等词、安排人/派人/分工/召集等委派词，或点名专家成员/角色（项目经理等，含自定义名）走专家团；一句话里包含多个工程动作（实现、重构、修复、设计等）的复杂需求走专家团；提问和单点小任务走智能体。

## 模式锁定
提交后选择器回显并锁定实际使用的模式，重进对话也恢复为该模式。模式仅在第一句话生效。

## 查看计划与完成
输入框上方的执行计划按钮展示完成数量和状态；悬停任务名称查看详情，其余详情收起；停止的任务显示待继续，只有实际运行才显示转圈。全部任务完成后浮窗经过短暂缓冲再消失；重新打开已完成对话不会重新弹出完成浮窗。

## 自定义专家与并行度
设置 → 对话的专家定义区可新建、编辑或删除专家角色：名称、图标和系统提示均可自定义，也可让 AI 辅助生成。内置角色可一键恢复。并行度控制同时执行的专家数量，默认按提供商类型自动选择（官方 API 3、第三方 2），也可手动指定 1–8。

# 退出后的恢复执行

重新打开程序后，未完成计划可通过“继续执行”恢复。

## 尽量避免重做
保留已完成子任务，核对中断前结果，再继续剩余任务。恢复的同一子任务会替换旧执行卡片。

## 边界
程序退出后不会继续运行。恢复不是进程级断点恢复：正在执行的命令可能已经部分完成，需核查文件与外部结果，避免重复操作。

# 工具调用与审批

模型读写文件、执行命令前，工具调用先经过安全规则，再根据策略进行 AI 预审或人工确认。

## 决策顺序
明确拒绝规则优先；直接允许规则可跳过普通审批。AI 预审失败、超时或证据不足时转人工。完整访问模式具有更广权限，需要单独选择。

## 查看原因
决策记录可按项目、对话、方案和层级过滤，查看具体规则与理由（日志保留见「历史与日志清理」）。

## 边界与注意
审批成功不表示命令一定成功：执行环境仍可能拒绝文件访问或其他操作。

<a id="chat-capabilities"></a>

# 在对话中选择技能、插件和 MCP

对话输入区的“技能、插件与 MCP”按钮汇总当前项目能使用的能力，不需要背诵工具名称。

## 操作步骤
1. 打开选择器，按全部、技能、插件、MCP 分类筛选。
2. 搜索名称、描述或来源；来源帮助区分同名工具。
3. 选择一项，调用标识插入光标处；已有草稿和附件保留。
4. 在草稿中补充目标、范围、输入和预期结果，再发送。

例如：选择一个报告技能后，补充“只检查本项目本周提交，生成 Markdown 报告”。选择器不会自动调用、发送消息或增加权限。

## 三类能力的区别
技能是模型按需读取的操作手册；插件工具是清单中 tool:true 的服务方法；MCP 工具来自已启用服务器的工具发现结果。仅安装的插件、停用服务器、未标记为工具的方法不会出现在这里。

## 列表为空或不完整
确认当前项目、技能作用域、插件有效启用状态和 MCP 测试结果。点击刷新可重新发现 MCP 工具。部分服务器失败时，其他可用能力仍然显示，并列出暂不可用来源。列表刷新不会提交草稿。

## 引擎与授权
此目录与 Sage API 对话工具链一致；CLI 引擎能否调用这些工具取决于该引擎桥接支持。发送后仍执行对话的文件、网络、插件权限与审批检查。选中能力不是批准它的所有未来操作。

<a id="context-strategy"></a>

# 上下文窗口与压缩策略

对话变长后会超出模型的上下文窗口。Sage 会在每次发送前自动「整理上下文」：驱逐过旧的轮次、必要时把被驱逐内容浓缩成摘要，保证请求不超窗。两个开关分别决定「整理力度」和「摘要质量」。

## 上下文压缩模式（整理力度）

决定保留多少近期历史、多早触发压缩。

- 自动（默认）：按本轮内容体量与工具调用数自动选择下面三档，无需手工调。内容偏短或偏写作时保守，内容较长时均衡，很长或工具调用很多时激进。
- 保守：上限约 160k tokens，保留最近 5 轮。适合大窗口模型、需要完整回溯的长讨论；代价是请求更大、更费 token、更慢。
- 均衡：上限约 120k tokens，保留最近 3 轮。大多数日常对话的平衡点（未选择时的缺省档）。
- 激进：上限约 80k tokens，保留最近 2 轮。适合超长对话、小窗口或低预算模型；代价是较早丢失早期细节。

显式限制优先：若在对话的上下文面板或设置中指定了固定窗口（如 200K tokens），以显式值为准，模式只影响保留轮数与触发时机。

## 摘要生成策略（摘要质量）

决定被驱逐的旧轮次如何浓缩。

- 自动（默认）：单轮内容超过 4,000 字符时调用已配置模型生成摘要，其余直接截断；模型调用失败自动回退截断。兼顾质量与成本。
- 简单截断（快速）：只保留开头片段。速度最快、不消耗模型 token；代价是丢失被截部分的语义。
- LLM 智能摘要（更准确）：每次都调用模型浓缩被驱逐内容。语义保留最好；代价是每次整理都额外消耗 token 与时间。

## 怎么选（适用场景）

- 追求省心：两个都保持「自动」，覆盖绝大多数场景。
- 长代码 / 多工具任务、怕丢细节：压缩模式「保守」+ 摘要「LLM 智能摘要」。
- 小模型 / 省 token / 要快：压缩模式「激进」+ 摘要「简单截断」。
- 写作 / 长文讨论类对话：压缩模式「保守」或「自动」，摘要「自动」即可。

## 查看整理记录

上下文面板（输入区九宫格图标）与 设置 → 上下文窗口 都可打开「整理记录」，记录每次整理的触发方式（自动/手动）、压缩模式、摘要策略、整理前后 token 数，便于评估当前配置是否合适。

<a id="model-providers"></a>

# 模型与后端

在设置中添加 Anthropic 或 OpenAI 兼容提供商，填写地址、凭据与模型。

## 选择模型
可以设置全局默认模型，也可以按项目和对话选择。视觉模型用于不支持图片的主模型的图片预处理；预处理失败需要检查请求监控器。

## 测试连接
填了模型时，「测试连接」会真实调用模型列表里的第一个模型（一次最小补全请求），通过与否以这次调用为准；没填模型时只能测接口连通性，不代表任何模型可用。服务不支持模型枚举（清单接口 404）不影响真实调用测试。

## CLI 引擎
CLI 后端通过插件接入：在设置 → 全局 → 插件配置安装对应 CLI 引擎插件并全局启用，然后在通用设置中选择引擎。CLI 需要本机安装和相应登录环境；详见「CLI 引擎插件」。

## 模型能力验证
设置中双击模型可触发能力探测，验证视觉、联网搜索、推理、工具调用等能力是否可用。自动探测在空闲时运行；手动探测立即执行。验证结果按模型汇总，展示各能力的支持状态和历史记录，并附带价格图表。



## 配置不生效的检查顺序
先确认对话是否覆盖了项目默认值，项目是否覆盖全局默认值，再看实际执行引擎。模型名称应与提供商支持的 ID 一致。连接测试成功不保证所有模型、所有工具和图片能力都可用，按实际所需能力验证。

## 无输出或限流
在请求监控中检查状态码、模型、阶段和错误：401/403 通常检查凭据与权限，429 检查额度或速率，超时检查网络与服务。不要在公开帮助请求中粘贴 API Key。CLI 登录状态与 API 提供商凭据是两套配置。

## 手机对话中的模型与设置

在手机对话的「＋ → 模型与思考强度」中，「跟随项目 / 全局」显示将继承的提供商、模型名称及来源，恢复默认时不会固定当前父级模型。复合和路由提供商显示配置的公开模型名，下游成员仍按请求路由。

配套桌面与手机 0.6.849 支持执行中修改模型、思考强度及对话安全方案。保存后从下一轮（包括下一条排队消息）生效，当前回复、工具、插话续轮和专家任务保持启动时设置。完全访问仍需确认。旧桌面缺少能力时保持只读，并提示升级；中继透传已有操作，无需同步升级。

# 复合提供商与模型映射

复合提供商将可用模型映射到不同的实际提供商，便于统一选择。

## 按时间切换模型
映射支持 `公开模型=成员模型|生效时段|替代模型`，例如 `qwen3.8-flash=qwen3.8-flash|22:00-08:00|qwen3.7-plus`。在生效时段内使用成员模型；其他时间改用已启用提供商中支持的替代模型。替代模型可属于另一提供商。省略第三段时，原映射仍只在配置的时段内可用。多个时段用逗号分隔，时间按本机时钟计算。

## 检查映射
先确认目标提供商已启用、模型可用，再保存映射。调用异常时查看请求监控器中的实际模型与错误。不要把界面展示名称当成服务端模型标识。

# 插件开发与加载

插件把工具、界面、技能和自动化处理器组合成可安装的软件包。先区分“已安装”与“在当前项目启用”：安装成功不代表所有项目都会运行它。

## 安装与使用
1. 打开设置 → 插件 → 插件包，选择离线包、市场安装或开发目录。
2. 查看插件身份、版本、依赖与申请权限；确认安装计划。
3. 根据需要打开全局启用，或只在项目配置中启用。
4. 打开“配置”填写必需字段；秘密字段只在全局配置中保存。
5. 在插件声明的侧栏、工具栏或标签页找到入口；对话内可用“技能、插件与 MCP”搜索工具。

## 开发目录
开发目录必须包含 sage.plugin.json 和清单指定的入口文件。加载后使用开发模式的启动、停止、重新加载更新服务。修改清单后重新加载并核对权限；旧安装的权限不会因为源码新增声明而自动增加。不要修改安装缓存作为长期源码。

## 内置与外置
Git、Browser 是始终可用的宿主模块，不能卸载或停用，也不再提供“左栏快捷按钮”开关。侧栏分区的展开与收起仍由工作区布局管理。Specs、Docs 和 CLI 引擎是独立插件，按安装状态与启用范围运行。

## 调用失败排查
入口不存在：检查当前项目、有效启用状态、依赖、贡献的 visible/when 与 slot 拼写。
方法不存在：服务与方法名必须同时出现在清单和 globalThis.sagePlugin.services 中。
权限拒绝：检查已授予权限，不只看清单声明；按正常安装流程重新审核。
服务报错：查看插件日志中的服务、方法、耗时和错误，再检查输入/输出是否符合 schema。

<a id="plugin-activation"></a>

# 插件列表与启用范围

全局启用是所有项目的默认值，项目覆盖只影响当前项目；“跟随全局”会移除项目覆盖。

## 三层状态
| 层级 | 含义 | 操作入口 |
| --- | --- | --- |
| 安装 | 本机已有经过校验的包 | 设置 → 插件 → 插件包 |
| 全局启用 | 项目默认是否使用 | 插件列表的全局启用 |
| 项目覆盖 | 当前项目单独启用或关闭 | 项目配置，恢复时选跟随全局 |

清单 scope 为 global、project 或 both，决定可配置的范围。Git、Browser 始终启用，不受旧版停用配置影响。

## 配置如何覆盖
全局字段作用于所有项目，项目字段只作用于当前项目，两种范围字段优先取项目覆盖。恢复继承与把值设为空字符串不是一回事：前者回退默认来源，后者可能是明确的空值。修改后观察保存错误提示；保存失败不能视为已生效。

## 为什么无法启用
检查缺少的依赖包、版本范围、宿主依赖和插件权限。先安装、启用依赖，再启用使用方。插件停用后，其服务、技能和订阅不应再进入当前项目的可用能力列表；对话选择器可手动刷新。

## 删除与恢复
卸载前先停用需要它的工作流。重新安装不等于恢复所有项目的启用覆盖；再次检查有效状态和配置。仅想临时停止功能时先停用即可。

# 二次开发：最小插件

适用插件格式 1、SDK 1.4 系列。普通插件运行在隔离服务中，不直接访问 Electron、Node 文件系统或宿主页面 DOM。

## 创建工程
1. 在设置 → 插件的开发区创建工程或选择独立开发目录。
2. 根目录放 sage.plugin.json，入口放 plugin.js；页面放 views/，技能放 skills/。
3. 清单 id 使用唯一的命名空间名称（例如 local.hello）；版本是 x.y.z。
4. 加载开发目录，核对校验结果与权限，启动并在当前项目启用。

## 最小可运行文件
下例不申请额外权限，提供对话工具和工具栏入口。工具栏点击显示完成状态；想查看返回字符串，可在对话中调用 hello.greet。

```json
{
  "format": 1,
  "id": "local.hello",
  "name": "Hello",
  "version": "1.0.0",
  "sdk": "^1.4.0",
  "entry": "plugin.js",
  "permissions": [],
  "services": {
    "hello": {
      "version": "1.0.0",
      "methods": {
        "greet": {
          "description": "Return a greeting",
          "input": {
            "type": "object",
            "properties": {},
            "additionalProperties": false
          },
          "output": {
            "type": "string"
          },
          "tool": true
        }
      }
    }
  },
  "contributes": [
    {
      "id": "hello",
      "slot": "toolbar",
      "title": "Hello",
      "service": "hello",
      "method": "greet"
    }
  ]
}
```

plugin.js:
```javascript
globalThis.sagePlugin = {
  services: {
    hello: { greet: async () => 'Hello from Sage' }
  }
};
```

## 逐步验证
先验证能加载，再在对话能力选择器搜索 local.hello，补充“调用并展示返回结果”。更改返回文字后重新加载，确认新结果生效。最后停止开发模式，导出 .sageplugin，在没有开发目录的环境导入验证。

## 常见错误
清单不是合法 JSON、入口路径错误、服务方法未实现、返回值不符合 output 都会导致校验或调用失败。描述文字不能代替正式 schema；增加功能时一次添加一个方法并验证。

## 资料位置
仓库 docs/plugin-examples/local.notes 提供含设置与页面的样例，resources/plugin-sdk/sage-sdk.d.ts 提供类型提示。docs/PLUGIN_MANUAL.md、EXTENSION_COOKBOOK.md 和 PLUGIN_EXTENSION_CATALOG.md 是进一步查询入口。

<a id="dev-services"></a>

# 二次开发：服务与宿主权限

插件的稳定接口由清单中的 services 定义，JavaScript 必须实现同名服务与方法。对话工具、UI 按钮、hooks 都复用这层接口。

## 输入与输出
每个方法写 description、input、output；需要在对话暴露时设 tool:true。schema 支持 object、array、string、number、integer、boolean、null 及 properties、required、additionalProperties、items、enum、长度和数值边界。不要假定支持完整 JSON Schema；不支持的关键字会在包校验时报错。

推荐对对象设置 additionalProperties:false，明确必填项和长度。方法返回前等待写入完成；抛出错误表示失败，不应在 catch 后无条件返回成功。

## 调用宿主
使用 sdk.host(service, method, args)，并在 permissions 声明所需权限。举例：workspace.read/write、git.status/commit、browser.list/open、channels.list/send 等由宿主校验。具体参数以随包类型与当前 API 手册为准，不可自造服务名。

普通插件没有直接 require('fs') 或任意 shell 能力。需要执行命令时使用受控的 tools.Bash 宿主服务，仍会经过标准审批与运行时沙箱。插件安装权限不是操作系统完全访问权限。

## 跨插件依赖
调用其他插件使用 sdk.call，并声明 consumes 与相应依赖版本。必需依赖安装/启用失败时，应给出可修复的错误；可选依赖缺失时保留主要功能。宿主 Git/Browser 使用 hostDependencies，不是可安装包的 dependencies。

## 配置与秘密
使用 sdk.settings.get/set 读写声明的配置；project、global、both 的覆盖规则与客户端一致。secret 仅支持 global。不要把密钥硬编码到清单、技能、HTML 或日志中。模型路由扩展返回提供商/模型引用，不返回 API Key。

## 验收
验证有效输入、缺少字段、额外字段、超长内容、类型错误、权限缺失、依赖停用、服务抛错及重新启用。对于真实写入或发送，只在已授权的测试目标验证结果。

# 二次开发：界面插槽与上下文

contributes 声明入口，服务方法负责执行，view 可打开插件自己的沙箱页面。UI 插槽不会赋予读取对话正文或任意 DOM 的能力。

## 可用插槽
| 区域 | 名称 |
| --- | --- |
| 标题栏 | titlebar.left、titlebar.right |
| 侧栏与页面 | sidebar.middle、sidebar.bottom、sidebar.tabs、tab、panel、menu |
| 通用与状态 | toolbar、status |
| 对话 | conversation、conversation.input、conversation.header、conversation.actions |
| 定时任务 | scheduled.toolbar、scheduled.task |
| 帮助 | help.toolbar |
| 工具栏 | editor.toolbar、git.toolbar、browser.toolbar |
| 设置 | settings、settings.navigation、settings.models、settings.context、settings.appearance、settings.appearance.colors、settings.skills、settings.mcp |

## 新增上下文插槽
conversation.header 位于输入区域上方，conversation.actions 位于对话操作栏，两者服务参数为 {context:{conversationId}}。scheduled.task 传 {context:{taskId}}，help.toolbar 传 {context:{topicId}}。scheduled.toolbar 是任务页通用入口，参数仍是空对象。旧插槽保持原参数协议。

这些字段只是定位标识，不含消息正文、附件、密钥或任务配置，也不提供绕过权限的读取接口。view 入口仅打开已声明页面，不自动向 iframe 注入上述上下文；需要上下文的动作应声明 service/method。

## 服务按钮示例
```json
{
  "id": "inspectTask",
  "slot": "scheduled.task",
  "title": "检查任务",
  "service": "taskActions",
  "method": "inspect",
  "when": "project",
  "order": 100
}
```
该方法 input 必须接收 context 对象中的 taskId 字符串，output 与实际返回值一致。不能在 input 中禁止 context 却又把方法挂到这个插槽。

## 交互规范
按钮执行期间禁用重复点击，失败显示原因，成功显示完成状态。写入结果由插件自己的页面、通知或返回内容呈现。标题应表达动作，badge 简短，order 决定同槽排序。项目切换后忽略旧请求的界面反馈；插件停用时入口随有效状态消失。

## 页面安全
页面通过桥接请求自身服务，不能直接操作宿主 DOM；不要依赖远程脚本、内联事件或不存在的 Node 全局。页面按宿主主题配色并支持窄窗口、键盘焦点和可读错误。查看完整 UI 桥接示例再添加交互。

# 二次开发：Hooks、事件与策略

先确定扩展是在做决定、接收通知、提供算法还是添加界面，再选择对应声明。

## 四种机制
| 需求 | 声明 | 结果 |
| --- | --- | --- |
| 对执行流程作出决定 | hooks | 按钩子协议解释结果 |
| 获知宿主事件 | events | 有界通知，不等同新授权 |
| 提供可选择的功能实现 | extensions / extensionPoints | 按版本与输入输出 schema 分派 |
| 展示用户操作入口 | contributes | 按钮或插件页面 |

## Hooks
在清单申请 hooks.respond，并把事件绑定到自己的服务方法。matcher 用于限定处理对象；order 控制顺序，timeoutMs 为有界等待。支持事件以随包类型和完整扩展清单为准。旧 hooks.json 不执行。不要让 hook 依赖长时间人工交互；超时、异常和无效结果应能够定位。

## Events
宿主事件包括 sage/workspace.opened、sage/settings.changed、sage/git.committed、sage/browser.created、sage/browser.navigated、sage/browser.closed、sage/engine.started、sage/engine.finished。订阅方法收到数据后仍受插件权限约束，不能把事件通知解释成用户授权发送或删除。

## 策略扩展
sage/context.compact 提供压缩摘要与保留轮数，需 context.transform；sage/models.route 返回 providerId/modelId，需 models.use。必须声明兼容版本、输入输出和服务方法，并在对应设置中选用。清单存在不意味着它会替换默认策略。

## 调试与兼容
分别验证无订阅、多个订阅、版本不兼容、权限缺失、停用、超时、异常和无效结果。检查调用链与依赖是否形成循环。兼容升级保留既有字段；需要破坏协议时使用新版本，别让旧调用方靠猜测适配。

<a id="dev-release"></a>

# 二次开发：调试、打包与升级

源码目录、运行中的开发实例、已安装包是不同状态。排查“修改没生效”时先确认当前运行的是哪一份。

## 开发循环
编辑源码 → 校验清单 → 加载/重新加载开发目录 → 在目标项目启用 → 调用 → 查日志。权限变化需要重新审核。多个窗口切换时确认项目配置相同；插件全局安装不代表各项目有效状态一致。

## 对话辅助开发
Plugin 工具提供 scaffold、inspect、dev-start、dev-stop、package、validate。让模型明确操作目录与插件 id，不要把源码直接写进宿主安装缓存。对话开发操作受当前项目范围限制。打包导出不执行第三方 package scripts；已存在的输出文件不会被无提示覆盖。

## 打包验收
1. 更新插件自身版本，检查清单、入口、页面、技能及类型引用。
2. 导出包并检查必要依赖；在干净项目中安装。
3. 验证配置持久化、停用/启用、卸载后入口消失、重新安装恢复流程。
4. 验证空值、错误、超时、离线、窄窗口、浅深主题和中英文文案。
5. 对写文件、发消息或网络请求使用明确的测试目标，核对实际结果。

## 升级与权限
新增权限不会被旧安装自动授予；用户应看到更新计划。包内容摘要变化时确认确实加载了新版本。依赖版本不满足时不要绕过校验，修正依赖或发布兼容版本。

## 发布资料
随包提供功能用途、安装/配置步骤、权限解释、已知限制、故障定位、变更记录和可复现示例。当前源码文档放在 docs/，生成到 SDK 的副本用于分发，避免维护两份相互冲突的说明。

<a id="skills"></a>

# 技能（Skills）

技能是可复用的 Markdown 知识包：模型在任务匹配时按需读取，相当于给对话加载一本手册。技能可独立安装，也可随插件包分发。

## 安装与作用域
设置 → 技能管理全局技能（对所有项目生效）；项目设置中的技能页管理项目级技能（仅当前项目）。同名时项目级优先。支持离线 Markdown/技能包安装、在线市场安装、创建工程与开发目录加载。

## 启用依赖
技能可以声明宿主依赖：例如外置浏览器验收技能需要先启用 Browser 宿主模块。有未满足的依赖时，复选框旁会提示「需先启用：…」并禁用勾选。

## 对话内使用
技能采用渐进式披露：名称与描述先进入对话上下文，正文由模型在需要时通过 Skill/Plugin 工具读取，不需要你手动粘贴。单个技能正文上限 128KB、描述 200 字。


## 编写普通技能
在项目 .sage/skills/ 下放置 Markdown 文件，或使用设置中的技能安装入口。文件前部可写 YAML 元数据：
```markdown
---
name: review-release
description: 检查当前项目发布内容并生成验收清单
---
# 发布检查
先读取项目说明，确认范围，再核验构建与测试结果。
```
描述用于匹配任务，应说明何时使用；正文写清输入、步骤、产物和失败处理。同名项目技能覆盖全局技能，插件同名技能采用确定的首个可用项；用唯一名称避免歧义。选择器显示来源，便于确认读到的是哪份技能。

## 技能不等于授权
技能说明不会自动扩大文件、网络或插件权限。正文要求的外部服务仍需已配置；凭据应放在对应秘密配置中，不应写进 Markdown。修改技能后刷新能力列表并发起新的明确请求。

<a id="mcp-servers"></a>

# MCP 服务器管理

设置 → MCP 服务器管理外部工具服务器，支持 STDIO 和 Streamable HTTP 两种传输方式。

## 加密环境变量
在服务器列表页的“MCP 加密环境变量”中录入密钥值。值会加密保存在本机设置，渲染界面只收到变量名和受保护占位符；值只用于 MCP 请求，不会注入终端或其他子进程。MCP HTTP 配置的 Bearer 环境变量字段填写对应变量名。

## 添加服务器
STDIO 需填写命令、参数、环境变量和工作目录；HTTP 需填写地址、令牌环境变量名和请求头。导入 JSON 可批量添加（导入后默认停用）。名称不可重复。

## 测试连接
点击测试会建立真实连接并拉取工具列表，显示可用工具数量和名称。

## 自动加载到对话
应用启动及 MCP 配置变更后，Sage 会在后台连接已启用的服务器并缓存工具清单。API 对话直接使用缓存；停用的服务器不会提供工具，连接失败的服务器会被跳过。调用仍遵循现有工具授权规则。

## 启用与导出
每个服务器可独立启用或停用。导出 JSON 生成不含密钥的模板，便于分享配置。

## 边界与注意
导入的服务器默认停用，需手动启用。环境变量中的密钥不随 MCP 模板导出；加密设置备份会保护本机变量。完整开发契约见插件 SDK 的 EXTENSIBILITY.md。


## 从配置到可调用
1. STDIO 使用本机实际存在的可执行文件；参数按项填写，确认工作目录和依赖已安装。
2. HTTP 填写服务器真实 MCP 端点，不能用普通网页地址代替；令牌字段填环境变量名，不是把密钥写进工具描述。
3. 保存，测试连接，检查发现的工具名，再启用。
4. 回到对话的能力选择器搜索服务器名；缺失时点击刷新。

## 缓存与恢复
已发现的目录被复用以减少发送延迟；后台按需刷新，失败来源会重试，选择器也能强制刷新。修改地址、环境变量或停用服务器后，旧目录不能把调用悄悄转发到新配置，需要重新发现。

## 常见失败
命令不存在：在终端验证完整路径，不假定图形应用继承你的 shell PATH。
连接超时：检查服务是否运行、代理、证书和端点。
有连接但零工具：确认服务提供 tools/list，而非仅资源或提示模板。
工具执行失败：区分发现成功与具体参数/权限失败，查看该次工具结果。MCP 返回的内容按数据处理，不应充当追加授权。

<a id="git-plugin"></a>

# Git 侧栏

Git 分区自动发现当前项目及其子目录中的仓库；Git 与 Browser 始终可用。先确认顶部仓库路径，再执行会改变分支、索引或远端的操作。

## 日常修改到提交
1. 在 Git 中打开工作区变更，选择文件检查差异。
2. 使用“暂存当前文件”或“暂存全部”。暂存表示准备提交，不会推送到远端。
3. 使用“取消暂存”可保留工作区内容，仅把修改移出暂存区；尚无首个提交的仓库也支持。
4. 输入提交说明，点击“提交暂存更改”。只有暂存区进入此次提交；未暂存修改保留。
5. 提交失败时保留说明并显示错误；检查冲突、Git 用户身份、提交钩子，再决定是否重试。

## Fetch、Pull、Push
| 操作 | 会改变什么 | 需要注意 |
| --- | --- | --- |
| Fetch | 下载对象、更新远程跟踪引用、清理已删除远程引用 | 不切换分支、不合并工作区 |
| Pull | 获取远端后快进当前分支 | 仅允许 ff-only，分歧时会拒绝 |
| Push | 上传本地提交到配置的远端/上游 | 首次推送选择远程并设置上游 |

每个仓库同时只运行一个修改操作；共享 Git 目录的 worktree 也共用这个限制。执行中显示状态并禁用重复触发。成功和失败都会刷新相关列表。

## 分支与标签
双击或右键分支可切换。远程分支可检出并建立本地跟踪分支；本地分支支持新建、重命名、删除、配置或取消上游。右键还提供合并、变基、快进更新以及新建标签。删除本地分支使用 Git 的已合并检查；远程删除会真实改变远端。不要把本地引用的删除与远端删除混淆。

历史行右键可从指定提交建分支，或检出提交。检出弹窗中留空会进入分离 HEAD；需要继续开发时填写新分支名称。所有输入都在程序内完成，取消不改变仓库。

## 历史与文件
按引用聚焦历史，使用搜索/分页浏览提交。查看父提交、改动文件和该提交的文件树。历史文本在只读标签中打开，图片可预览；查看历史文件不会覆盖工作区。长分支名可悬停看完整名称。

## 配置
设置 → 插件 → Git 中可设置仓库扫描间隔、分支前缀、force-with-lease 推送与提交说明指引。分支前缀仅对不带命名空间的新名称应用；已有前缀或包含 / 时不重复添加。强制推送选项会改变推送行为，开启前确认这是你需要的历史重写流程。首次发布分支使用普通推送。

<a id="git-recovery"></a>

# Git 故障与冲突恢复

先读错误内容，确认仓库路径和当前分支；不要用反复点击或强制推送掩盖问题。

## 拉取被拒绝
“无上游”：首次推送并选择远程，或在分支菜单配置已存在的上游。
“无法快进”：本地与远端各有提交。先 Fetch，比较历史，再选择合并或变基；Sage 的 Pull 不会替你自动选择策略。
“本地修改将被覆盖”：先提交需要保存的修改，或在终端按你的工作流 stash；切换分支不会自动丢弃文件。

## 推送失败
检查远程 URL、网络、SSH agent 或凭据助手。Sage 不会弹出隐藏终端让你输入密码；可以在终端完成认证配置后重试。
non-fast-forward 表示远端包含本地没有的历史，先获取并整合。不要仅为消除错误开启强制推送。force-with-lease 也不是备份，且服务器保护分支仍可能拒绝。
分离 HEAD 不适合作为日常推送起点；从该提交创建本地分支后再发布。

## 解决合并或变基冲突
1. 打开工作区变更，检查冲突文件中的双方内容。
2. 用编辑器保留需要的结果，移除冲突标记，保存。
3. 暂存解决后的文件，确认没有剩余冲突。
4. 合并可提交暂存结果；变基用分支菜单“继续变基”。
5. 不想继续时使用“中止合并”或“中止变基”。中止由 Git 恢复操作前状态；操作前已有复杂修改时先核对 Git 的提示。

## 仓库或历史不对
确认当前项目与所选子仓库，手动刷新。后台扫描优先使用缓存以加快切换；刷新会重新读取。没有 origin 不代表不是仓库；首次推送可选择其他已配置远程。刚初始化且尚无提交的仓库没有历史，这是正常状态。

## 提交失败
提示作者身份缺失时，在终端为该仓库配置 user.name 与 user.email，再重试。钩子失败时根据其日志修复；Sage 不会自动跳过钩子。空提交说明不能提交，未暂存文件也不会自动加入提交。

## 精确核验
需要确认实际结果时，在对应仓库终端查看 git status、git branch -vv、git remote -v、git log --oneline --decorate -10。涉及凭据的输出不应粘贴到公开报告。

# 桌面宠物

桌面宠物是独立的透明悬浮窗口，可拖到显示器可见工作区的任意位置，用文字或语音发起项目对话，并查看回复和后台消息。

## 启用与配置
设置 → 通用 → 桌面宠物。总开关、宠物形象、宠物对话方式放在同一设置区，修改后自动保存。形象可选像素猫、漫画猫、像素狗、漫画狗；宠物右键菜单也可切换。形象“关闭”只隐藏图片，保留常驻的小入口；关闭桌面宠物总开关才会全部隐藏。

对话方式默认“同一个对话持续进行”，在当前宠物会话里复用同一项目的对话；换项目时创建新对话。选择“每次新建对话”则每次发送都新建。

## 文字与语音
1. 鼠标靠近宠物，出现编辑和语音两个按钮。点击编辑才展开输入条；点击加号选择最近项目。
2. 输入文字后点击发送或按 Enter。未选项目时先选择项目；回复显示为气泡，完整内容可在主窗口查看。
3. 语音按钮直接开始录音，变为黑色圆点；点击圆点停止。已选项目且有转写时自动发送，未选项目时保留转写供选择项目后发送。麦克风、识别服务和输入设备使用客户端的语音设置。
4. Escape 返回小入口。鼠标离开约 300 毫秒后收起工具条，保留草稿、项目与录音会话；再次靠近继续操作。形象关闭时小入口与展开的输入条保持常驻。

## 贴边、四角与打招呼
拖到屏幕可见工作区的边缘时，只露出头和爪，待机时会眨眼。拖到四个角落时沿对角探头，朝屏幕内部露出头和爪。鼠标靠近时轻轻点头打招呼，并显示对话和语音入口；每次靠近招呼一次，停留不会反复重启动作。

对话框、项目面板与消息气泡朝屏幕内部展开：左边向右、右边向左、上边向下、下边向上；四角同时沿两个方向向内展开，探头留在角落。操作工具和收到消息都保持探头贴边。离开后工具条收起，草稿保留；有消息的气泡按自身规则收起。

轻点探头会向内跑出来，四角沿对角出来；按住移动超过 4 像素后拖动，松开不会误触跑出。沿边拖动时保持探头，向内拉开约 48 点后露出全身。菜单栏和 Dock 不属于可见工作区。

## 拎起与位置
按住全身拖动会变为悬空垂爪姿态，围绕颈部轻摆。悬空身体保留正常比例并使用更高的显示空间，不因塞进正方形而突然变小。松手有约半秒的落地回弹，不会自动滑到屏幕底部。拖动时暂停待机和鼠标互动。

位置与贴边方向保存在本机 pet-state.json，重启后恢复；副屏移除时回到当前可见屏幕。位置不随设置备份迁移。

## 消息与权限

# 定时任务

在对话中描述时间、工作内容、范围和结果去向；Sage 生成任务确认卡，保存后才进入计划。也可在定时任务页新建。

## 创建步骤
1. 说明频率或一次性执行时间，并指定项目与目标，例如“每天 9 点检查本项目构建状态，把摘要写回这个对话”。
2. 在确认卡检查名称、指令、计划、模型、超时时间、授权方式和输出目标。
3. 有来源对话时可继承来源授权；也可关闭继承，选择独立安全方案。
4. 保存后核对下次执行时间。先手动“立即运行”验证模型、工具和输出配置，再等待计划触发。

## 执行与输出
任务用独立的 API 执行上下文运行，不覆盖你正在输入的对话。可写入指定对话、输出新对话、投递渠道或静默执行。结果工作流可添加条件子步骤；条件不匹配的节点不执行其后续分支，匹配结果按配置投递。

## 时间与生命周期
按本机时区计算，需要 Sage 运行。任务页显示下次时间与上次结果；恢复后的逾期周期会合并补跑，同一任务不重叠执行。暂停只停止未来触发，查看当前运行状态判断是否仍有执行。关联对话归档后会暂停有关任务，避免继续写入已归档对话。

## 修改、导入和导出
编辑后保存完整配置；遇到“任务已变化”请重新加载再编辑，避免覆盖另一处修改。导出是可分享的配置模板，不带来源对话的授权快照。导入后默认暂停，需要检查模型、目标对话、渠道和安全方案，再启用。

## 记录与审批
展开运行记录可区分执行失败、等待审批、超时与投递失败。需要超出已有授权时仍会等待人工决定，未及时处理会按任务超时结束。模型执行成功而渠道投递失败，不等于任务内容执行失败；先检查投递记录再决定是否重跑。

# 定时任务如何继承授权

可以继承，但任务获得的权限不能超出确认时的来源对话。对话生成的新任务默认勾选继承，确认卡可查看或改成独立方案。

## 继承哪些内容
- 来源对话实际生效的安全方案快照，包括文件、命令、网络与预审规则。
- 来源对话中可重复使用的具体工具调用授权：工具名及完整参数必须匹配。
- “本对话全部允许”不会作为无限授权复制；只保存该授权下已经确认或实际通过的具体调用。
- 一次性批准、已经消费的执行凭证、系统麦克风/屏幕权限不会被复制。

例如，允许某个 Bash 命令访问一个指定域名，不会顺带允许另一个命令、不同端口或额外目标。插件工具的方法与参数、MCP 工具标识也参与匹配。任务中新的调用仍按继承的安全方案决策，必要时等待审批。

## 授权何时失效
每次运行会检查来源对话、项目和安全方案。来源不存在、被归档、项目不匹配，或方案内容、启用插件代码/权限/配置、MCP 地址/环境发生变化时，原快照不能继续使用，任务会显示错误。先检查来源对话的当前方案，再编辑任务并保存，明确重新捕获授权。仅暂停或重新启用不会自动扩大授权。

## 重启与后续修改
保存到任务中的具体调用快照可以跨重启保留；来源对话之后新增的临时授权不会自动追加到旧任务。重新保存时只捕获此刻仍可获得的来源授权。旧任务没有快照时沿用原先的独立方案行为，不会无提示升级权限。

## 独立方案与导入
取消继承后可选择任务自己的安全方案。插件直接创建、手动新建且没有来源对话的任务不能凭空继承。导出的任务文件不包含可复用授权快照；导入后重新配置独立方案并检查输出目标。

## 遇到重复审批
对照运行记录中的工具名、路径、命令、域名与参数，确认是否与之前授权完全相同。动态文件名、不同查询参数或新目标可能需要新审批。不要为消除提示把任务改成完全访问；先按实际工作范围调整来源方案。

# Spec 工作流概览

Spec 用需求、设计、任务三份文档组织开发：先明确要做什么，再细化怎么做，最后拆成可执行任务。Spec 是可选插件，先安装并在项目启用 Specs 插件，再从侧栏 specs 入口创建或查看。

## 三个阶段
1. 需求：描述目标、使用场景与验收标准。
2. 设计：细化方案、约束与取舍。
3. 任务：拆解成可执行、可检查的条目。

## 边界与注意
文档确认不等于放开工具权限：执行仍受安全策略控制（见「工具调用与审批」）。各阶段入口与操作取决于已安装的 Specs 插件版本。

## 架构全景
侧栏的架构视图按钮展示项目中所有 Spec 的架构全景：按工程维度分类，显示任务进度和完成状态，便于纵览整体工程进展。

# Loop 自主迭代

Loop 以目标和评估结果驱动多轮改进：设定目标与评估指标后，循环自动执行、评估、调整，直到达标或触顶预算。可用入口取决于当前安装和启用的插件（如 delivery-loop）。

# 安全方案与文件沙箱

在“安全与授权”中管理方案，在对话输入框旁选择生效方案。

## 生效时机
方案名称可同步展示；执行策略变更在下一次开始或恢复执行时生效，不改变正在运行的操作。

## 文件边界
命令默认不能联网，且受项目文件范围、受保护配置和环境变量约束。批准普通命令不会解除沙箱。网页工具的域名规则不控制命令的网络权限。

## 文件列表目录过滤
设置 → 安全与授权的文件列表目录过滤可指定要从文件列表、文件名搜索和内容搜索中隐藏的目录名（如 .sage、tmp）。过滤对所有项目生效，不删除文件也不控制模型访问权限。默认隐藏 .sage 目录。



## 方案外观与管理
方案可设置名称、说明、图标与颜色，便于区分。图标和颜色选择器可点外部关闭，Esc 关闭并返回触发按钮；未选择不改动值。一次只展开一个选择器。更改外观不会更改工具执行权限。

## 人工批准的范围
一次批准只处理当前请求；可重复批准按具体工具与参数复用；对话范围授权仍受确定的拒绝规则与执行沙箱约束。定时任务继承需要另存快照，参见“定时任务如何继承授权”。

<a id="sandbox-network"></a>

# 保留沙箱，联网单独审批

编辑安全方案，在“直接允许”下启用“保留沙箱，联网单独审批”。

## AI 预审后人工批准
模型使用 Bash 的 network=true 和 networkReason 申请联网，说明用途、目标和发送数据。AI 先预审：拒绝会拦截；建议允许、无法确定、失败或超时均交给你最终决定。使用配置的预审模型，未指定则跟随对话。

## 授权范围
点击“仅本次允许联网”后，仅该命令及其子进程可向任意 IP 地址发起连接；文件隔离不变，不开放监听。说明中的域名不是强制限制，网页域名列表也不限制此权限。

## 失败处理
授权单次使用，命令、策略或已检查脚本变化会使授权失效。下载失败时重新申请，不应关闭文件沙箱或绕过拒绝。

## 诊断记录的内存限制

<a id="troubleshooting"></a>

# 常见问题与排查顺序

描述问题时附上操作入口、期望结果、实际错误、当前项目和版本，比“不能用”更容易定位。先核对状态，不必先重装或清空数据。

## 对话和速度
| 现象 | 先检查 | 对应帮助 |
| --- | --- | --- |
| 模型不对 | 对话/项目覆盖、执行引擎 | 模型与后端 |
| 一直等待 | 是否在审批、工具、队列或模型请求阶段 | 工具调用与审批、请求监控 |
| 输入变慢 | 是否在录音、优化输入或有大附件 | 语音输入、上下文策略 |
| 回答中断 | 错误记录、已完成工具、可恢复状态 | 退出后的恢复执行 |
| 费用或词元增大 | 历史长度、图片、工具输出、压缩策略 | 上下文窗口与压缩策略 |

## 插件、Git 和任务
| 现象 | 先检查 | 对应帮助 |
| --- | --- | --- |
| 找不到插件按钮 | 是否安装、项目有效启用、依赖、slot | 插件列表、界面插槽 |
| 技能同名或未出现 | 项目覆盖、名称唯一性、刷新 | 技能、能力选择器 |
| MCP 无工具 | 启用、连接测试、真实端点、刷新 | MCP 服务器管理 |
| Pull/Push 拒绝 | 上游、分歧、认证、未提交修改 | Git 故障与冲突恢复 |
| 定时任务未触发 | 应用运行、启用状态、时区、下次时间 | 定时任务 |
| 任务要求再次授权 | 参数变化、来源方案变化、快照状态 | 定时任务如何继承授权 |
| 执行成功但没收到结果 | 输出目标、渠道可用性、投递错误 | 渠道接入、运行记录 |

## 界面与系统
快捷键无反应先看焦点、模态窗口、重复绑定；录音无声检查麦克风和语音识别权限；截屏失败检查屏幕录制权限。历史文件不能编辑时确认是否只读 Git 快照。文件列表缺项检查目录过滤，不要先删除项目缓存。

## 收集信息
在帮助中确认版本；复制具体错误，必要时查看请求监控、插件日志、决策记录和任务运行记录。截图前检查凭据与私人内容。备份设置再尝试有破坏性的恢复；不要把删除整个数据目录当成常规修复。

<a id="memory-merge"></a>

# 长期记忆与自动融合

记忆分三层：当前对话（.sage/chats/<id>/memory.json）> 项目（.sage/memory.json）> 全局（~/.sage/memory.json）。同一件事只保留一条。

## 写入即融合
新增记忆时按字符相似度查重：同一层里已有相同表述、或只差几个字的冲突表述，不再新增条目，而是并入既有条目——正文以最新一次写入为准，标签取并集，首次创建时间保留，被替换的旧说法记在该条的 mergedFrom 里。若新写入的内容只是旧条目的缩略复述，则保留更完整的旧正文，避免细节越写越少。

## 冲突与优先级
内容冲突时以更新时间最新的一条为准；生效范围仍是当前对话 > 项目 > 全局。跨层不互删：全局和项目各有一条时，项目那条压住全局，删任一层不影响另一层。对话注入时同一件事只给最新一条。

## 历史重复
旧版本遗留的重复会在打开设置 → 记忆时自动分层合并；合并前原文件备份到同目录的 .merge-backups/（每层最多保留 5 份）。备份失败时宁可不合并也不删除。

# 多窗口协作

可为不同项目打开独立窗口，每个窗口拥有独立的标签页、终端和对话状态。

## 打开新窗口

# 语音输入与授权

语音听写把识别结果放进当前对话草稿；不会自动发送。请先选择正确对话，再开始录音。

## 两种快捷键
| 模式 | 默认按键 | 行为 |
| --- | --- | --- |
| 按住说话 | Fn | 按住开始，松开停止；离开窗口自动停止 |
| 手动开关 | Fn + Control | 按一次开始，再按一次停止 |

两种模式都只在 Sage 窗口内生效，可在设置 → 键盘快捷键重新绑定或取消绑定。输入框旁麦克风按钮与手动开关一致。持续按键不会反复切换。若已经手动录音，按住模式不会抢占该次录音。

## 首次授权
macOS 的麦克风和语音识别是两项独立权限。按提示授权；被拒时点“打开系统设置”进入对应面板。授权等待期间松开按住键会取消本次开始；授权后需要重新按住，不会突然继续采音。

## 录音与停止
录音期间输入框显示转写，分段会拼接。停止后检查文字再发送。切换对话、关闭窗口或开始优化输入会停止采音，避免内容进入错误草稿。手动模式录音中可再次按快捷键或麦克风按钮停止。

## 输入设备与排查
设置 → 通用可选择麦克风；未指定时跟随系统默认。刷新设备会请求权限并重新扫描。
无文字：确认设备有声音、系统权限已允许、语音助手可用；查看界面显示的具体错误。
识别不准：降低环境噪声，确认应用语言，中英文混说的效果仍受系统识别影响。
按键无反应：确认焦点在 Sage、没有正在录制快捷键、没有模态弹窗，并检查冲突或已取消绑定。

## Fn 键说明
macOS 使用原生 AppKit 事件识别 Fn/地球键。按住 Fn 说话；Fn + Control（Fn⌃）切换录音，两种按键顺序都支持。设置中录制 Fn 组合时松开 Fn 完成。原生模块不可用会显示提示；没有 Fn 的键盘可以重新绑定。已有自定义绑定保留，点“恢复默认”使用上述按键。

# 截屏、标注与复制

默认 Shift + Cmd + A（⇧⌘A）冻结鼠标所在显示器的桌面并显示半透明蒙版。快捷键只在 Sage 窗口内响应，可在设置中修改。对话、设置、文件页面使用同一套屏幕选区与标注工具。

## 使用
1. 让 Sage 获得焦点，按截屏快捷键。
2. 在桌面蒙版上拖出选区：外部压暗，内部保持清晰，选区旁实时显示导出的像素尺寸。
3. 在选区内拖动可移动范围，拖动八个边角控制点可调整大小；确认前随时可以修改。工具栏跟随选区并避开屏幕边缘。
4. 点击绿色勾号（Enter / Cmd + C），把编辑后的图片复制到剪贴板并关闭编辑器；或点击下载图标（Cmd + S），选择位置保存 PNG。
5. 需要发到对话时，自己回到目标输入框按 Cmd + V，再检查并发送。

截图不会自动加入草稿或发送。复制和保存是两个独立出口，保存不会覆盖剪贴板。取消保存会保留当前编辑，保存或复制失败也会保留图片供重试；红色叉号或 Esc 关闭编辑器。截屏失败和权限提示都在独立截屏窗口显示。正常结束时蒙版平滑渐隐；系统开启减少动态效果时直接关闭。

## 调整选区
选区工具下可直接拖动内部；画图时拖动边框、控制点，或按住空格拖动，仍可调整范围。调整选区不会缩放背景或标注；超出选区的内容不会导出。在选区外重新拖动可重选范围。Cmd + A 选中整个显示器；拖动中按 Esc 撤回本次拖动，再按 Esc 退出。

多显示器时，使用工具栏的显示器下拉框，或按 Control + Tab 切换。每次选择一个显示器，不跨屏拼接；切换或重新截屏成功后重新选择范围。显示器断开、旋转、分辨率或缩放改变时会退出当前截屏，避免位置错位；Dock 工作区域变化不影响选区。

## 标注工具
- 矩形、圆形、箭头：按住鼠标拖画。
- 点击标注工具展开小面板：三个圆点选择线条粗细，色块直接选择蓝、绿、黄、黑、白或红；再次点击可收起。画笔支持拖动画线。
- 马赛克：拖选要打码的区域，输出 PNG 会把打码结果合并到图片。
- 文字：点击图片直接输入，三个 A 选择字号；可重新点击已有文字继续修改，支持多行。
- 表情：小面板提供 48 个表情，可滚动选择，方向键按六列导航；选择表情和大小后点击图片放置；马赛克用三个圆点选择颗粒大小。
- 选区：移动或调整要保留的范围；撤销可恢复前一次范围。
- 撤销 Cmd + Z、重做 Shift + Cmd + Z；最多保留 200 步编辑。
- 重新截屏：隐藏蒙版后重新读取屏幕；失败保留当前选区和编辑，成功替换为新的完整背景。

## 修改标注
确认复制或保存前，标注一直可编辑。点击已有框、圆、线、画笔、马赛克或表情重新选中，再调整色块、粗细或大小；选框的八个点可缩放，拖动边框或图案可移动。空白处开始新标注，Esc 取消当前编辑或选择。

点击文字直接输入，重新点击可改内容、颜色和字号。Delete / Backspace 或小面板的垃圾桶删除选中标注；撤销、重做同样适用于移动、缩放、修改和删除。使用“调整选区”、绿色边框或按住空格调整最终截图范围；导出不含标注选择框和输入框。

## 权限与限制
首次截屏会请求屏幕录制权限。需要授权时点击“打开系统设置”，在隐私与安全性 → 屏幕与系统录音（或屏幕录制）中开启 Sage，再回来重新截屏。macOS 要求重启时，退出并重开 Sage。

截图文件最多 24 MiB，最多 24 × 1024 × 1024 像素，单边不超过 16384 像素。常见 Retina 屏幕保留原像素；超高分辨率或多屏超过内存预算时，背景会按比例缩小，尺寸提示始终对应最终图片像素。读取多屏缩略图的估算总量限制为 48 × 1024 × 1024 像素。捕获不产生临时图片文件，关闭截屏即释放图片和编辑历史。粘贴到对话后仍遵循对话配置的图片大小上限及模型视觉能力。

## 多个 Sage 条目
旧版曾从 dev.sage.app 迁移到 sage.app；历史签名或多份安装也可能留下同名记录。仅凭显示顺序无法确定哪条属于当前安装。在“应用程序”中打开当前 Sage，在设置 → 安全与授权 → 系统权限查看当前实际状态和应用标识。安装更新不会自动合并历史系统权限条目。开发态 Electron 的权限与安装版 Sage 分开处理，无法识别身份时不会重置其他实例的权限。

## 无反应或失败
检查 Sage 是否在前台、有无模态窗口或快捷键冲突、是否正在读取屏幕。屏幕读取超时后可稍候重试，未结束的原生请求不会重复堆积。编辑器已经打开时重复触发会回到现有编辑器。归档对话、输入优化和录音期间不触发截屏。当前交互截屏面向 macOS。

工具栏支持 Tab 导航，方向键切换工具和选项。Control + Shift + Tab 反向切换显示器。截图背景绘制完成后才显示。

# 键盘快捷键

设置 → 键盘快捷键管理应用快捷键绑定，支持搜索、重绑、重置和冲突检测。

## 分组与搜索
快捷键按窗口与终端、对话、编辑器和预览查看四组分类。搜索框可按名称、描述或默认按键过滤。

## 重绑与重置
点击铅笔图标进入录制模式，按下目标组合键即完成重绑，Esc 取消。每条快捷键可单独恢复默认，也可一键全部重置。不可重绑的快捷键显示锁定图标。

## 冲突检测
同一组合键被多条快捷键使用时，冲突项标红并悬停显示对方名称。单独按键允许方向键、功能键和翻页键；Fn 单键及 Fn 组合仅用于两种语音操作。

## 边界与注意
快捷键改动立即生效并跟随设置保存。macOS 显示符号（⌘⌃⌥⇧），其他平台显示文本。


## 语音和截屏
按住说话默认 Fn，手动录音开关默认 Fn + Control，截屏默认 Cmd + Shift + A。都只在 Sage 窗口内生效。录制新组合时按键不会触发原有操作；Esc 退出录制。按住模式松键、失焦后停止，快速松键也会取消仍在等待系统授权的开始动作。

## 冲突排查
Cmd + A 与 Cmd + Shift + A 是不同按键。设置中若发现重复绑定，清除其中一项或换成其他组合。Fn 使用原生事件识别。系统或其他应用的全局快捷键仍可能先于 Sage 处理；可在对方设置中取消冲突绑定。
