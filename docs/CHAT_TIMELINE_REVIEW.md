## 0.6.527：澄清与上下文计量

- 澄清卡片逐题显示，支持题号导航、字母选项、多选和自定义回答；切题保留草稿。所有题目回答后统一提交，失败可重试。推荐按钮只选择题目中明确标记的推荐项，不自动提交；取消会结束当前待答请求。
- 上下文计量优先使用最新请求构建估算，否则使用最近一次请求的 `contextUsage`。不再把多次工具迭代累计的计费用量当作上下文体积；旧数据缺少单次用量时不伪造读数。
- Anthropic 单次上下文输入包含普通输入、缓存读取和缓存创建；累计计费用量不变。估算值不显示缓存比例；超出窗口时显示实际百分比，进度图形仍限制在满格。
- 整理失败中的“边界之前”仅指可被摘要替换的前缀；它不是整个上下文大小。整理记录中的前后数值属于当次历史估算，不能与后续请求的用量直接比较。词元及相关提示提供中英文显示。

## 参考与设计依据

- [Claude Agent SDK：agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)：一次完整执行包含多条助手消息、工具结果和最终 result；单条文本或工具消息结束不等于整个执行结束。队列释放必须以执行函数收尾为界。
- [Martin Fowler：Event Sourcing](https://www.martinfowler.com/eaaDev/EventSourcing.html)：从有序事实重建视图。本次借鉴接收位置记录、事件序号和快照后增量回放；没有引入完整事件存储系统。

## 原有问题与修复

| 问题 | 原因 | 修改后 |
| --- | --- | --- |
| 插话实时顺序与结束/重载后不同 | 整轮结束才物理拆分助手消息；快照还反向查找 `!pending`，容易命中旧回复 | 接收时记录正在输出的助手 ID、正文长度、工具数量；展示层即时投影 |
| 连续插话出现重复消息 ID、重复用量 | 拆分 ID 只取正文偏移；每段复制完整用量 | 使用原消息 ID 和插话 ID 生成稳定片段 ID，用量/错误只保留在末段 |
| 停止后旧执行和下一条并发 | 删除 aborter 后用 50ms 定时器 drain | 停止/关闭窗口仅发取消信号；真实收尾前保留执行锁 |
| 重复恢复导致两个 drain 同时运行 | drain 缺少入口排他检查 | 每个对话单个 drain，迭代处理；所有入口检查执行锁和 drain 锁 |
| 排队消息回答前插到了错误位置 | 通过“第一条 queued”猜身份 | clientMessageId 与 queueId 精确关联，开始执行时移到当前历史末尾 |
| 延迟回执覆盖下一轮输出/忙碌状态 | 整个 `r.meta` 覆盖 store，旧发送的 finally 清空新执行状态 | 输出由事件更新；完成/忙碌由后端 turn_state 决定 |
| 排队/重排与新消息竞态丢气泡 | 前端用旧队列列表回写 | queue_update 下发权威队列，重排回执不再覆盖列表 |
| 切换对话丢流式内容或重复文本 | 历史和队列分两次读取，加载期间事件丢失 | 一次读取历史、队列、运行状态和序号；缓冲并回放快照后的事件；去重 |
| 冷启动同时发送的历史各写各的 | 两次并发磁盘读取生成两个缓存对象 | 合并同对话的并发加载；运行中的缓存对象保持引用稳定 |
| 插话被接收但没有送入模型 | 纯文本/SDK 没有下一个工具边界，结束时清空插话 | 原执行结束后，对未消费插话顺序续答，再处理消息队列；不重复插入用户消息 |
| 重试回答了错误的问题 | 从最后一条用户消息推断失败请求，可能拿到插话 | 明确保存失败请求；续答失败记录续答文本 |
| 时间戳跨天后改变消息日期 | 收尾时覆盖创建时间 ts | 保留 ts，更新 updatedAt |
| 分叉后插话位置丢失 | 消息 ID 改变但位置引用未同步 | 分叉重映射位置引用，并保留该回复期间的插话 |

## 行为约定

1. **普通对话**：用户消息、助手过程和最终内容保持原顺序。正文仍流向原助手消息，工具结果按 call ID 更新。
2. **插话**：按接收时的实际正文/工具位置显示。之后到达的正文显示在插话之后。连续插话、相同正文偏移以接收顺序排列。已开始的工具卡保留原位置，完成时更新其结果，不复制工具调用。
3. **队列**：待执行消息在独立队列面板中显示。前一执行、未消费插话续答和持久化收尾完成后，才激活下一条。
4. **停止与失败**：当前执行完成取消/错误收尾，队列暂停；用户选择继续或重试后恢复。不会在固定延时后自动启动新操作。
5. **异常回执**：后到达的 send/reorder 返回值不覆盖更新的流式内容。暂停状态下继续提交的消息保留在队列，界面不误显示正在回答。
6. **切换/重载**：接收位置随普通历史保存。运行期事件序号用于去重与加载期间回放；快速切换不会被更早的读取请求抢回焦点。
7. **模型上下文**：展示片段不直接改写原始模型消息/工具结果结构。分叉时保留接收位置引用。末段的操作通过原始消息 ID 定位。

## 自动化验证

命令：`npm run test:chat-timeline`。

脚本直接加载实际编译后的 IPC 注册函数、实际 Zustand store 和共享时间线投影。模型执行由可手动结束的异步假实现替代，IPC 边界使用结构化克隆。测试无需 API key，不调用付费模型。

27 个场景全部通过：

- 普通历史及队列与正文分离。
- 流式插话前缀冻结、后续正文位置、JSON 重载一致性。
- 相同偏移、连续插话、多轮唯一 ID、空白正文保留。
- 插话前开始的工具在插话后返回，结果更新且不重复用量/错误。
- 回执前开始执行、重排后的精确身份匹配、未知/重复激活事件。
- 快照保留其他未提交消息，清理已完成请求的占位。
- FIFO 等待消息结束/持久化；并发恢复不抢执行权。
- 取消超过 50ms 仍保留执行权，收尾后暂停待恢复。
- 纯文本/SDK 的未消费插话续答先于下一条排队消息。
- 已在安全边界消费的插话不重复请求。
- 空闲时插话只生成一条用户消息。
- 初始请求失败也暂停队列；重试目标不被插话覆盖。
- 意外异常结束 pending 并暂停后续消息。
- 取消、合法重排、重复 ID 排列拒绝。
- 冷缓存并发发送共用历史对象，保持串行。
- 调度器直接调用 runOneTurn 后也处理后续队列。
- 实际 store 在 queue_start 早于入队回执时保留新输出和忙碌状态。
- 切换加载期间补齐文本并去重。
- 快速切换对话不被旧读取覆盖。
- 后台失败只更新对应对话状态。
- drain 执行期间的新入队消息不丢失。
- 插话续答失败记录续答文本。
- 快照加载期间新入队消息只回放一次。
- 分叉重映射位置引用并保留插话。
- 前端 busy 残留由后端执行事件恢复。
- 关闭窗口时执行锁保留到真正收尾。
- 暂停后继续入队，不假忙且剩余数量正确。

构建验证：Electron TypeScript 编译通过；Vite 前端生产构建通过；`git diff --check` 通过。

## 验证限制与兼容性

- 未调用真实模型验证各供应商网络/SDK 行为。已补充实际 React DOM 渲染和浏览器视觉冒烟验证；独立 Electron 进程在当前主机被 SIGKILL，尚未完成桌面进程全链路联调。
- 旧历史若已被原逻辑错误拆分且没有接收位置记录，无法可靠推断当时的真实顺序；本次不猜测改写旧数据。
- 队列仍是进程内瞬态状态，可在切换窗口/刷新渲染器后恢复；应用进程退出后不恢复未执行队列。本次未新增任务队列持久化。
- 专家并行输出仍沿用各专家消息的组织方式；本次没有将多专家输出改造成全局逐事件日志。
