# Sage 独立插件平台设计建议

> 历史设计草案：下面的“当前实现与缺口”描述提案时状态，现已部分完成，不是当前 API 规范。
> 当前能力请看 [扩展架构](EXTENSIBILITY.md) 和 [场景化二开手册](EXTENSION_COOKBOOK.md)。

2026-09-13。本文保留设计时的分析与目标，不作为已完成清单。0.6.285 已实现独立包、宿主隔离、服务依赖、浏览器示例和开发工作台；实际接口、场景与未完成部分见 [插件手册](PLUGIN_MANUAL.md)。

## 当前实现与缺口

- `src/plugins/types.ts` 的 SagePlugin 只有侧栏、标签页和主视图贡献，没有版本、依赖、入口、激活或卸载协议。
- `src/plugins/registry.tsx` 静态导入 specs/docs/git/browser，项目 enabledPlugins 只筛选展示，不是安装、隔离或能力授权机制。
- `src/plugins/browser/index.tsx` 直接依赖 useAppStore；BrowserView 持有 webview。浏览器的生命周期、界面和行为耦合，不能把组件直接作为稳定的跨插件 API。
- `electron/ipc.ts` 已有 WebviewEmulate/CDP 设备模拟入口，但尚不能据此认为已有完整的浏览器自动化服务。
- `electron/channels/registry.ts` 是另一套内置通知渠道注册表，需要作为同一插件平台的 channel 贡献点接入，而非再发展一个安装系统。
- `electron/agent-bridge.ts` 已有 MCP 工具注入接点，可以适配插件工具；还需要逐一覆盖其他执行后端，避免只在一个模型后端可用。

## 目标边界

插件放在独立工程，开发、运行、测试和打包不依赖 Sage 源码；用户拿到插件包，可离线安装和运行。涉及外部模型、网站等服务的调用仍需要网络与使用者自己的凭证。

主程序负责窗口、项目、模型调用、持久化、权限、调度、审计与插件宿主。插件通过有版本的 SDK 使用这些能力。开发态与安装态使用相同协议；开发环境有全部宿主能力的调试入口，可使用真实项目联调，也可使用隔离数据。能力覆盖全面，不意味着把内部 Zustand store、任意 IPC 和明文凭证暴露给插件。

功能完整性的可检验标准：建立宿主能力清单，逐项列出 SDK、权限、模拟实现和契约测试；迁移后的内置插件也仅依赖公开 SDK，暴露缺失接口。

## 运行架构

采用三层结构：

1. 宿主服务层：模型、项目、文件、对话、任务、通知、配置、凭证代理、窗口与权限。
2. 插件管理与调用层：包校验、依赖求解、激活、服务发现、消息路由、授权、调用链、超时取消、崩溃恢复。
3. 插件层：独立逻辑运行环境 + 可选隔离 UI + commands/tools/services/channel/views 贡献点。

外部插件不能直接作为 React 组件导入主界面。UI 使用隔离视图和消息桥，主题、多语言及通用控件由 SDK 提供。逻辑通过异步 RPC 调用宿主；请求携带宿主签发的插件身份、项目作用域、调用链及取消信号，参数和结果均作 schema 校验。

独立进程首先解决崩溃隔离，不自动实现安全隔离。Electron utilityProcess 有 Node 能力；若任意插件能直接访问 fs/net，则 SDK 权限检查不足以构成边界。普通第三方插件优先使用无 Node 的受限执行环境；需要原生模块/子进程的插件必须进入明确的高信任运行模式或受 OS 沙箱约束。调试器默认仅本机访问，不开放未认证控制端口。

## SDK 与跨插件服务

### 全界面贡献点（补充需求）

用户明确要求左中栏、左下角、Tab、配置项等已使用位置均可参与插件化设计。将应用布局改造成命名插槽与贡献注册表，内置功能也通过这些插槽注册：

| 位置 | 贡献类型及可控逻辑 |
| --- | --- |
| 左侧中部 | 导航项、项目树分组、列表、详情视图、徽标；点击命令及显示条件 |
| 左下角 | 快捷操作、状态入口、账户/连接状态项、弹出菜单 |
| 主区域 Tab | 打开/激活/关闭、标题/图标/徽标、脏状态提示、关闭钩子、恢复状态 |
| 设置 | 全局/项目分类、分组、schema 表单、自定义面板、校验、默认值、迁移及备份归属 |
| 辅助区域 | 底部面板、调试输出、任务状态、侧边详情、通知 |
| 工具与菜单 | 工具栏、右键菜单、命令面板、快捷键、对话附件与操作入口 |
| 对话 | 工具结果卡片、操作按钮、进度、可选内容渲染器；工具行为使用统一服务调用 |

每个贡献包含 namespaced id、slot、order/group、声明式 when 条件、command 或 view、配置作用域及必要权限。when 使用受限表达式读取公开上下文，不能执行任意宿主 JS。既支持宿主原生表单/列表控件，也支持需要复杂交互的隔离自定义视图。

贡献项可在运行时更新状态、标题、徽标或可见性。插件能管理自己创建的 Tab 与视图，操作其他插件的内容需要对方公开接口及授权。默认为向插槽追加；替换宿主功能需专门声明可替换点并由用户选择实现，避免多个插件抢占或覆盖核心导航。插件管理与恢复入口应始终由宿主保留。

顺序由用户布局优先、其次贡献分组/顺序、最后稳定 ID 决定；重名、快捷键冲突和不兼容插槽均给出诊断。停用时撤销所有贡献，取消订阅并处理有未保存内容的 Tab，不丢弃草稿。恢复布局时缺失插件显示可恢复占位，重新安装后可继续打开。

设置字段以插件 ID 命名空间隔离，明确 global/project/session 作用域、是否敏感、是否可备份。普通项操作即保存，跨字段事务或长文本编辑器可局部保存；读取失败不得用默认值反写覆盖。插件配置纳入既有版本化备份，导入时逐插件/模块覆盖或忽略，并验证对应 schema 与迁移版本。

开发工作台提供“界面插槽检查器”：显示当前每个区域的插槽 ID、贡献者、命令、可见条件及排序，支持对话指令“把这个入口放到左下角”“新增一个项目设置项”，并在开发宿主即时预览。这是公开扩展契约，不允许插件遍历或修改宿主 DOM。

建议能力空间：workspace、files、models、conversations、tasks、ui、settings、secrets、events、services、tools。SDK 对象只是客户端代理，状态以宿主为准。

插件可以发布有名称和版本的 service；其他插件声明依赖后通过服务代理调用。主程序和 AI 工具也走同一服务实现，避免界面、程序调用、AI 调用三套行为。

service 面向程序组合；tool 是为对话设计的、有说明及输入输出 schema 的适配层。不是所有底层方法都直接暴露给模型。高风险动作经过现有安全与授权机制，审核应看到最终动作及完整发起链。MCP 可作为工具对外接入协议，但不承担插件包、UI、生命周期或安装依赖管理。

每次调用携带不可伪造的 caller / origin / project / capability，插件 A 调用浏览器 B 不能借用 B 的权限访问 A 无权使用的会话。凭证以句柄和宿主代调用方式使用；日志、调试与打包输出均不能返回受保护明文。

## 依赖链规则

区分三类依赖：包内 JS 库（随包构建）、插件运行依赖（其他已安装插件）、宿主 SDK 兼容版本。插件版本与服务契约版本分别声明。

- 使用 publisher.name 稳定 ID、SemVer 范围及锁定的精确版本/内容哈希。包内声明 required、optional 和提供/消费的 service 版本。
- 第一版在同一运行作用域中每个插件只激活一个版本，对所有依赖统一求交；冲突时拒绝变更并展示链路，不静默升级共享依赖。
- 检测传递依赖与环，拒绝必需依赖环并展示 A → B → C → A。可选关系不建立强制启动依赖，通过服务出现/消失事件绑定；同步调用仍限制深度与截止时间。
- 按拓扑顺序激活，依赖就绪后启动使用者；失败不留下部分可调用服务。停用时按逆序释放资源。
- 区分全局已安装与项目已启用：安装依赖不自动授予权限，不强行启用其他项目的插件。
- 卸载/停用前展示反向依赖。默认阻止破坏必需依赖，可显式连同依赖者停用；不自动删除用户数据。
- 对在途调用执行排空或明确取消，再换版本；订阅、定时器、浏览器句柄和任务注册均自动释放。
- 开发插件覆盖仅作用于指定开发会话，不能替换全局生产依赖。

离线分发提供单插件包和带依赖包的集合两种导出方式；“拿到一个文件就可用”应默认选择后者。导入前展示完整依赖图、安装/更新清单与权限差异。

## 打包、安装与数据保护

建议 `.sageplugin` 为带清单的归档格式，包含 manifest、编译产物、UI 资源、API schema、使用说明、许可证、依赖锁和文件哈希；源码与 source map 可选。名称是提案，尚非现有格式。

普通插件运行不要求用户安装 Node/npm。原生依赖需预构建并标记 OS/架构/ABI；不兼容包在激活前拒绝。安装不得自动执行任意 npm lifecycle 脚本。

安装流程：暂存解包 → 路径/链接/大小/数量限制 → 清单和兼容性检查 → 依赖计划 → 完整性及发布者信任检查 → 数据快照与迁移 → 激活健康检查 → 原子切换。哈希用于检测损坏，签名结合可信发布者才提供来源保证，不能混为一谈。

代码按 ID/版本不可变存放，数据单独按插件/作用域存放。插件设置使用 schemaVersion、事务、历史快照和恢复机制。失败保留旧代码与旧数据；数据迁移回滚必须与代码回滚成对处理，不能仅换回 JS 文件。跨多插件更新需有事务日志，重启后识别未完成安装并恢复。

插件包默认不带用户配置、浏览器 profile、Cookie、历史、API Key 或运行日志。配置迁移由独立的加密备份流程完成，延续受保护字段只用不读的约束。卸载默认保留数据，清理数据是独立操作。

## 浏览器插件作为首个完整样例

将现有 BrowserView 拆成 browser service 与 view，标签页、会话和 CDP 连接由明确的拥有者管理。关闭或切换 UI 不应意外终止正在执行的自动化任务；任务结束按生命周期释放。

公开接口应覆盖：

| 能力 | 建议接口 |
| --- | --- |
| 会话与页面 | session.create/close、tabs.list/create/close、navigate/back/forward/reload |
| 观察 | snapshot、screenshot、DOM/可访问树、文本查询 |
| 交互 | locator/click/fill/select/press/scroll、frame 定位 |
| 同步 | 等待导航/元素/下载、取消、超时、失效句柄错误 |
| 调试 | console、网络事件、请求失败、设备模拟、trace |
| 文件与身份 | 受作用域限制的上传/下载、会话复用；Cookie 管理单独授权 |
| 扩展控制 | 受控的脚本执行与 CDP 方法，按能力授权而非任意直通 |

标签页句柄包含项目、会话、拥有者和代次，避免关闭后 ID 复用控制到错误页面；并发任务采用页面级操作租约，用户接管时暂停自动化。CDP 会话需要统一管理，不能让设备模拟与自动化相互抢占调试连接。

建议验收：一个独立的网页信息整理插件声明依赖 browser service，在 UI 隐藏时也能打开测试网页、读取信息、截图并返回对话；整个包集合导入全新用户环境后重复成功，不修改 Sage 源码。

## 对话式开发工作台

开发流程：描述目标 → 生成独立工程与 manifest → 选择依赖/API → 启动开发宿主 → 对话触发测试 → 聚合失败日志和调用链 → 修改热重载 → 打包 → 干净环境安装验证 → 导出。

工作台提供 API 搜索及类型说明、模板、源码定位、断点/source map、前端预览、服务调用面板、事件监视、依赖图、权限检查、测试数据、性能与崩溃信息。浏览器任务可记录并回放脱敏操作轨迹；没有依赖时能模拟接口，但最终必须对真实依赖做契约测试。

对话调用开发工具（拟议）：plugins.scaffold / dev.start / inspect / test / package / installPreview。CLI 和 UI 是相同流程的另一入口，不能让聊天中断导致构建状态丢失。错误返回结构化诊断而非把所有日志塞进上下文。生成代码、构建、测试可自动推进，涉及当前真实权限和数据的操作沿用用户授权。

## 实施顺序与验收

1. 固定 SDK 和 manifest/schema，提取宿主服务，建立完整能力清单。
2. 完成运行隔离、服务路由、依赖求解、安装事务与配置迁移；建立故障注入测试。
3. 用浏览器插件迁移验证架构，同时做一个消费 browser service 的独立插件。
4. 提供对话开发工作台、热重载、调试、打包与干净环境安装测试。
5. 按同一协议迁移 git/docs/specs/通知渠道，后续再考虑插件市场。

必须覆盖：传递/菱形/环依赖、缺失/冲突依赖、升级后依赖不兼容、激活崩溃、安装中断、数据迁移失败、卸载依赖者提示、未知来源包、解包路径逃逸、调用身份伪造、跨项目访问、权限撤销、页面接管、运行中停用，以及开发态/安装态一致性。

- Electron [utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process) 与 [安全指南](https://www.electronjs.org/docs/latest/tutorial/security)：进程隔离和安全边界分别设计。
- [MCP Tools](https://modelcontextprotocol.io/specification/draft/server/tools)：参考工具描述和调用协议；链接为草案，正式实现应固定所采用的协议版本。
