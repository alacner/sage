# 图片预览功能

## 聊天图片的两种提交方式

自 0.6.746 起，输入框的两种入口具有不同的发送行为：

| 入口 | 预览标识 | 发送内容 | 用途 |
| --- | --- | --- | --- |
| 图片按钮、粘贴或拖入图片 | 无底部标签 | 图片内容 | 看图分析、截图排查；自动适配主模型视觉能力 |
| 回形针附件按钮选择图片 | 文件附件 | 本地文件路径 | 供 Agent 读取或作为项目素材处理 |

普通图片缩略图不显示底部标签；文件附件保留图标、文字标签和虚线边框。放大预览显示文件名和提交方式说明；同一张图片用两种方式添加也可正确区分。草稿切换和恢复保留该方式，普通发送、排队和插话均按同一规则分流。附件路径保留在模型请求和会话存储中，但自动生成的附件说明与路径不显示为聊天正文气泡；用户自行输入的路径照常显示。文件内容不会直接进入视觉输入。

文件附件依赖原文件仍在本机，并受 Agent 文件访问权限限制。改用附件不会让不支持视觉的模型自动获得看图能力；仍需使用视觉工具。若无法获取本地路径，会明确提示，不会悄悄改为模型图片。

验证：`node scripts/test-chat-rendering.cjs` 覆盖双入口、标识、放大预览、草稿恢复、删除、混合发送与仅附件插话。

## 内置自动视觉解读（0.6.747）

直接粘贴、拖入或用图片按钮提交图片即可，不需要 skill。主模型已有视觉能力检测结果时优先采用该结果（中继和复合提供商使用真实模型名称匹配，不使用编码后的请求 ID）；未检测的模型按保守规则判断，无法确认支持时先解读。

- 主模型支持视觉：直接传图片，不额外调用视觉模型。
- 主模型不支持或无法确认：按**对话 → 项目 → 全局**选择视觉模型，围绕用户的问题解读，再仅把解读文字和原问题交给主模型。CLI 引擎未向宿主声明视觉能力时也走预处理。
- 添加图片后，仅在主模型不支持或无法确认视觉能力时显示对话视觉模型选择器，可覆盖继承值或恢复跟随；主模型支持视觉时整块隐藏，切换模型后自动更新。浏览器视觉验收也使用同一继承顺序。
- 无可用配置、解读失败、拒识或超时：明确报错，不会继续把原图发给文字模型。取消会中断预处理。
- 解读结果保存在消息元数据，后续追问和 CLI 历史恢复保留视觉上下文；API 执行中的图片插话同样分流。

回形针文件附件仍只传路径，不会擅自读取和解读。视觉解读会产生一次额外请求，可在请求监控中查看。结果是模型对图片的解读，可能有遗漏，不能代替原图。

验证：`npm run test:vision-routing` 使用隔离的提供商替身验证继承、鉴权来源、解读、失败/超时/取消、历史与多模态载荷；不声称实测外部模型效果。

## 功能概述

现在 Sage 支持直接在文件树中预览图片文件。点击左侧文件树中的图片文件，会在右侧编辑器区域直接渲染预览，而不是显示为二进制文件。

## 支持的图片格式

- PNG (.png)
- JPEG (.jpg, .jpeg)
- GIF (.gif)
- WebP (.webp)
- SVG (.svg)
- BMP (.bmp)
- ICO (.ico)

## 技术实现

### 1. 后端 (Electron 主进程)

**文件：`electron/files.ts`**

添加了两个新函数：

- `isImageFile(path: string): boolean` - 判断文件是否为图片（基于扩展名）
- `readFileAsBase64(projectPath, relPath): Promise<FileReadBase64Result>` - 读取图片文件并返回 base64 编码的 data URL

图片大小限制：10MB（防止内存溢出）

**文件：`electron/ipc.ts`**

添加了 IPC 处理器：

- `IpcChannels.FilesReadAsBase64` - 处理图片读取请求

**文件：`electron/preload.ts`**

暴露 API 到渲染进程：

- `readFileAsBase64(projectPath, relPath)` - 供前端调用

### 2. 前端 (渲染进程)

**文件：`shared/types.ts`**

添加 IPC 通道常量：

```typescript
FilesReadAsBase64 = 'files:readAsBase64'
```

**文件：`src/lib/lang.ts`**

添加辅助函数：

- `isImageFile(filenameOrPath: string): boolean` - 判断文件是否为图片

**文件：`src/stores/appStore.ts`**

修改 `OpenFile` 接口：

```typescript
interface OpenFile {
  // ... 其他字段
  imageData?: string;  // 图片文件的 data URL
}
```

修改 `openFile` 方法：

- 检测文件是否为图片
- 如果是图片，调用 `readFileAsBase64` 获取 base64 data URL
- 将 `imageData` 存储到 `OpenFile` 对象中

**文件：`src/components/FileEditor.tsx`**

添加图片渲染逻辑：

```typescript
{file.imageData ? (
  <div className="file-image-preview">
    <img src={file.imageData} alt={file.relPath} />
  </div>
) : (
  // 其他文件类型
)}
```

**文件：`src/styles/index.css`**

添加图片预览样式：

- `.file-image-preview` - 容器样式（居中、自适应大小）
- 图片最大宽度/高度：90% 的父容器
- 保持宽高比

## 使用方法

1. 在左侧文件树中展开目录
2. 点击任意图片文件（.png, .jpg, .svg 等）
3. 图片会在右侧编辑器区域直接显示
4. 图片会自动缩放以适应编辑器大小，保持原始比例

## 注意事项

- 图片大小限制为 10MB，超过此限制的文件不会加载
- 图片预览是只读的，无法编辑
- 图片以 base64 编码加载到内存中，大量大图片可能会占用较多内存
- SVG 文件支持矢量预览，放大不会失真
