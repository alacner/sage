# Codex CLI 后端使用说明

Sage 支持 Claude CLI、Codex CLI、Qoder CLI 和 API 直连。Codex CLI 用于普通对话，以及使用 Sage 工作流执行通道的 Spec 规划与任务执行。专家多模型协作、独立配置的模型预审等功能继续使用各自配置的模型，不因切换对话引擎而改变。

## 安装与选择

1. 安装官方 Codex CLI：`npm install -g @openai/codex`。
2. 在终端运行 `codex login`，按提示完成登录。
3. 从插件市场或离线包安装 `sage.engine-codex` 并全局启用，再打开 Sage「设置 → 通用 → 后端引擎」，选择 **Codex CLI**。它不是内置引擎，不随 DMG 提供。开发与安装见 [后端引擎手册](BACKEND_ENGINES.md)。操作后自动保存。
4. 可执行文件路径留空时，依次探测登录 Shell 的 PATH、常见安装路径及本机 Codex/ChatGPT 应用内的 CLI。也可以填写完整路径，例如 `/opt/homebrew/bin/codex`。
5. Codex 模型留空时使用 CLI 的默认模型；也可以填写当前账号可用的模型名称。对话输入区显示正在使用的引擎和模型，点击可以返回配置。

可执行文件状态仅表示能运行 `--version`，不表示账号已经登录或额度可用。认证、模型可用性及服务端错误会在实际发起对话时返回。

Codex 使用当前用户的常规 Codex 登录存储。Sage 不把 API 提供商密钥复制给 Codex，也不自动回退到收费方式不同的 API 引擎。需要切换时，在通用设置中选择原来的引擎即可。

## 场景一：继续已有对话

选择 Codex CLI 后，在现有项目对话中输入「继续检查上一轮的实现」。首次切换会把已有对话的文字和工具记录作为上下文传给 Codex，之后沿用独立的 Codex 会话。Claude 会话标识与 Codex 会话标识分别保存。

编辑、删除、压缩历史，或使用其它引擎产生新消息后，Sage 会重新建立 Codex 上下文，避免恢复与当前历史不一致的旧会话。重新建立时使用已有文字和工具记录；旧图片不会重新上传，需要再次查看的图片请重新附加。当前轮附加的图片会直接传入 Codex，是否支持图片取决于所选模型。

## 场景二：修改项目文件并运行检查

发送「调整这个组件，并运行类型检查」。Codex 发起的文件、命令、网络和插件工具调用经过 Sage 的工具执行器；普通对话继续显示 Sage 的批准或澄清交互。切换对话安全策略后，下一次开始或恢复执行使用新策略，当前执行继续使用已有快照。

Codex 的原生执行工具被关闭；原生文件执行环境设置为只读，原生授权请求会被拒绝。选择完全访问权限时，Sage 动态工具按该权限执行，不受普通策略的沙箱限制。Codex 配置中的额外 MCP 服务在 Sage 会话中禁用，工具能力统一由 Sage 提供。Sage 不把模型传入的伪造批准标记当作授权。

点击停止会取消 Sage 正在等待的工具操作，并关闭当前 Codex 进程。停止不会回滚已经完成的文件修改。连接失败时不会自动重跑整轮，避免重复已完成的操作；查看当前文件状态后，可以明确要求继续。

## 场景三：Spec 插件工作流

选择 Codex 后，使用 Sage 工作流通道的规划阶段使用只读工具，执行阶段使用 Sage 的命令策略与项目文件策略。规划会话与执行会话分别保存，不混用工具权限。

工作流任务没有普通对话的交互批准通道。需要人工批准的操作会返回拒绝原因，可转到对话中完成批准与执行；不会静默放行。插件若直接调用自己配置的 API 服务，则仍由该插件管理，不受此后端选项替换。

## 备份与排查

- 配置备份选择「后端引擎」，会包含所选引擎、Codex 路径和模型。导入时沿用该模块的覆盖或忽略设置；不包含 Codex 登录凭据。
- 找不到程序：在终端确认 `codex --version`，再填写完整路径。
- 无法认证：在终端运行 `codex login` 后重试。
- 模型不可用：清空模型名称使用 CLI 默认值，或填写账号可用的模型。
- 协议不兼容：更新官方 Codex CLI。集成依赖 app-server 的实验性动态工具协议；已用本机 `0.154.0-alpha.6.2` 验证握手与工具注册。
- 请求监控记录文本与 token 用量。CLI 未提供实际账单金额，界面的通用估算不等于 Codex 账单；实际额度和计费以 Codex 账号为准。

## 验证范围

`node scripts/test-codex-bridge.cjs` 使用本地协议夹具验证流式输出去重、图片、续接、token 统计、取消、进程退出、授权拦截及重复工具调用只执行一次。附加 `--local` 会使用本机 ChatGPT 应用内的 Codex，在临时 HOME 中验证真实 app-server 握手与动态工具注册，不读取现有登录凭据，也不发送模型请求。

官方协议参考：[Codex app-server](https://developers.openai.com/codex/app-server)。

## 0.6.743 / 引擎 1.0.4 的恢复约束

会话标识携带工作目录与工具定义指纹。工具兼容时继续原生线程；旧线程或工具变化且存在 Sage 历史时，建立新线程并明确提示迁移，原线程保留。本机 app-server 的 `thread/resume` schema 不含 `dynamicTools`，因此不能靠传入未知字段宣称已更新工具。缺少历史时，指纹不匹配会明确失败；未带指纹的旧工作流线程保留原生恢复，不保证获得新增工具。

明确的线程不存在错误可用 Sage 历史恢复；连接中断或模型执行失败不自动重跑。取消先发 turn/interrupt，最多等待 750ms 后关闭进程组；屏蔽异步审批/工具的迟到回调，拒绝其他线程/轮次的事件及重复工具副作用。多次 token 通知按累计差值计量，避免重复计数。

浏览器跨轮复用、人工接管和验证边界见[浏览器联动](BROWSER_PREVIEW.md)。本轮验证包含协议夹具与真实 CLI 握手；未将握手检查描述为联网模型验收。
